## Dev environment: Conductor + portless

- `.conductor/settings.toml` (checked in) bootstraps every new Conductor workspace — there are no `scripts/*.sh` helpers anymore. `file_include_globs = ".env*"` makes Conductor **copy** the gitignored env files into the workspace (gitignore syntax, so it's recursive: `apps/*/.env.local`, `packages/backend/.env.local`, and `packages/backend/convex/.env` are all picked up — adding another app needs no change here, unlike the old symlink loop). `[scripts] setup = "bun i"` installs deps, and `[scripts.run.dev]` runs `bun run dev` as the default run script. The file also pins the workspace prompts (`create_pr` branch-naming/PR conventions, `general` Simplified-Chinese replies).
- Because env files are **copied**, not symlinked, a change to the root checkout's `.env.local` after a workspace was created does **not** propagate — re-copy by hand (or recreate the workspace) when you rotate a key.
- Both frontend apps (`apps/web` and `apps/dashboard`) use `portless run vite dev` — [portless](https://github.com/nicepkg/portless) assigns stable named localhost URLs per app, derived from each workspace's package name (e.g. `https://web.localhost` and `https://dashboard.localhost` here, plus worktree-specific subdomains automatically). (There's no Better Auth `trustedOrigins` to configure anymore — auth is a same-origin session token, and the backend's `/api/*` Hono router has no routes and no CORS middleware today.)
- **The portless proxy daemon must be running before `bun dev` URLs work.** It binds to port 443, doesn't survive a reboot, and the auto-start path silently fails when sudo isn't available — so after every reboot, run `sudo portless proxy start` once before `bun dev`. `portless run` will print "Proxy is running" and register routes either way (those are persisted on disk), but if nothing's bound to 443 (`lsof -nP -iTCP:443 -sTCP:LISTEN` empty), `https://*.localhost` will refuse the connection. The local CA installed on first run does persist via the system keychain, so no repeat trust prompt.
- The shared Vite config in `packages/vite-preset/src/index.js` sets `eventBusConfig: { port: 0 }` on the TanStack Start devtools plugin to avoid `EADDRINUSE` when running multiple worktrees concurrently. Both apps' `vite.config.ts` is a 3-line delegation to `createAppConfig()` — edit the preset, not the app file.
