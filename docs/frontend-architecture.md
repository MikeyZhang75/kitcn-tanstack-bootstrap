### Frontend: TanStack Start + TanStack Router

- Entry: `apps/web/src/router.tsx` creates the router (`defaultPreload: "intent"`). Route tree is file-based and generated into `routeTree.gen.ts` (gitignored).
- Route segments `_authenticated` and `_public` are **layouts**, not URL prefixes:
  - `_authenticated.tsx` is **`ssr: false`** (client-only, so the localStorage-based gate can run — there's no SSR pass) and gates access (see [auth](auth.md)): a cheap token-presence check in `beforeLoad` plus the authoritative role check in the component via `useSession()` (antd `Spin` while pending, redirect to `/auth` if the token is missing/stale, `/access-denied` on role mismatch). It renders the **shared authenticated shell** — an antd `Layout hasSider` wrapping `AppSidebar` (`Layout.Sider`) and an inner `Layout` with a `Header` (collapse trigger) + `Content`. All pages under `_authenticated/` render inside this shell.
  - **Shell scroll containment**: the shell caps itself at viewport height so long pages scroll inside the content region, not the page. The outer `Layout` is `height: "100dvh"` and `Content` is `minHeight: 0` + `overflow: "auto"` (`minHeight: 0` is what lets the flex child shrink below its content). If you reintroduce a `100dvh`/`100vh` wrapper on a page or drop either of those `Content` styles, you'll get a double scrollbar back — the whole page scrolls instead of just the content area. `hasSider` must also stay explicit: `AppSidebar` is a wrapper component, so antd can't auto-detect the `Sider` child and won't apply the horizontal flex layout. See [UI components](ui-components.md) for the full shell listing.
  - `_public.tsx` is a bare `<Outlet />` — no guard — and is also **`ssr: false`**, so the whole app is client-only (a SPA): with both layouts client-rendered there's no SSR of route content anywhere, only the prerendered shell the Cloudflare Worker serves. Pages that need "bounce already-signed-in visitors" (like `/auth`) put that check in their own `beforeLoad`, which now runs on the client even on hard loads (localStorage is available); pages that should be reachable regardless of auth state (like `/access-denied`) just live here and inherit nothing. (TanStack's plugin `spa` mode is also enabled in `@repo/vite-preset`; its build-time shell prerender runs in-process via `@cloudflare/vite-plugin` (Cloudflare Workers), so it builds with no `wrangler pages dev` spawn. The per-route `ssr: false` here is kept as a fallback for when that flag is off. See [auth](auth.md).)
- Current routes under `_authenticated` **in `apps/web`**: `index.tsx` (dashboard placeholder). The sidebar in `components/app-sidebar.tsx` has one nav item: 仪表盘 (`/`). Add new feature slices as sibling folders under `_authenticated/` and extend the `navItems` array.
- **`apps/dashboard` is an admin-only app sharing plumbing with `apps/web`.** Present routes: `_authenticated/index.tsx` (dashboard placeholder), `_authenticated/invitations/index.tsx` (invitation-code management — offset-paginated list, create dialog, revoke dialog), and `_authenticated/settings/index.tsx` (registration settings — a single-card `Switch` for whether signup requires an invitation code, reading the public `settings.getRegistrationSettings` query and writing the admin-only `settings.setRequireInvitationCode` mutation). `app-sidebar.tsx` has three nav items: 仪表盘 (`/`), 邀请码 (`/invitations`), and 设置 (`/settings`); the sidebar header title is "管理后台". Shared **app-level** plumbing (`components/providers.tsx`, `routes/__root.tsx`, `routes/_public.tsx`, `routes/_public/access-denied.tsx`, `routes/_authenticated.tsx`, `styles.css`, `tsconfig.json`) is byte-identical across the two apps. When you change any of those shared files, **mirror the edit into both apps in the same commit** — there's no shared-frontend package for app-level code today and the duplication is intentional (keeps each app's bundle scoped to its own audience's UI). The byte-identical set also covers `components/nav-user.tsx` and `routes/_public/-lib/zod-rule.ts`. (`routes/_public/auth.tsx` is _not_ byte-identical — `web` has a sign-up toggle, `dashboard` is sign-in only — and `_authenticated.tsx` differs only in the required role literal.) UI comes from **Ant Design v6** imported directly from `antd` in each app; there is no shared UI package (`packages/ui` was deleted along with Tailwind, shadcn, `lucide-react`, and `sonner`) — see [UI components](ui-components.md). The Convex plumbing (cRPC provider, query client, error normalizer, the `localStorage` session store, the `useSession` / `useSignIn` / `useSignUp` / `useSignOut` hooks, and `useAuthedCRPC` — the proxy that threads `sessionToken` into authed calls so no call site writes it by hand) lives in `packages/app-convex` — there is no per-app auth client anymore (Better Auth is gone). `app-sidebar.tsx` is per-app (different nav items + sidebar header title); the user menu it renders in the sider footer is `components/nav-user.tsx`, which reads `useSession()` / `useSignOut()` itself and only takes a `collapsed` prop. The Vite config lives in `packages/vite-preset` as `createAppConfig()` so each app's `vite.config.ts` is a 3-line delegation, and plugin / `optimizeDeps` changes only happen in one place.
- **Route-local code lives in sibling `-`-prefixed folders (FSD-style slices).** TanStack Router's file-based router skips any path segment starting with `-`, so folders like `-components/`, `-lib/`, and `-model/` are invisible to the route generator and a natural home for code that only one route uses. **Each route directory is a self-contained slice** with its own `-components/`, `-lib/`, `-model/` sub-folders — slice boundaries are per-route, not shared across siblings. The `apps/dashboard/src/routes/_authenticated/invitations/` slice is the canonical reference: `index.tsx` (route entry) with `invitations/-components/` (dialogs, columns, data-table, row actions, status badge), `invitations/-lib/` (status labels), and `invitations/-model/` (row type, pagination reducer).

  Prefer this per-route isolation over dropping single-use code into `apps/<name>/src/components/`. `_public/-lib/zod-rule.ts` (the zod→antd `FormRule` bridge shared by `/auth`) is the same idea one level up: a `-`-prefixed folder scoped to the `_public` layout group. Code shared across the whole app (the sidebar, the user menu) belongs in `apps/<name>/src/components/`; anything genuinely generic now comes from `antd` itself rather than a local wrapper.

- Providers tree (`components/providers.tsx`): antd's `ConfigProvider` (locale `zh_CN`) wraps antd's `App`, which wraps `AppConvexProvider` (from `@repo/app-convex/convex-provider`) → `ConvexProvider` → `QueryClientProvider` → `CRPCProvider`. `AppConvexProvider` takes only `children` — no `authClient` prop and no Better Auth bridge / auth store (identity rides in each authed procedure's input, so the Convex client attaches no auth). The bare `ConvexProvider` (from `kitcn/react`, plain `convex/react` context, no auth attached) is **required even though every call goes through cRPC**: kitcn's `mutationOptions()` resolve through `useConvexMutation` (`convex/react`), which reads `useConvex()` — drop the provider and every mutation (e.g. `session.signIn`) throws "Could not find Convex client". Better Auth's `ConvexAuthProvider` used to supply this context; the plain `ConvexProvider` replaces it. The package owns the `ConvexReactClient` instance, the query-client singleton, and the cRPC provider. antd's `<App>` replaced Sonner's `<Toaster>`: get toasts with `const { message } = App.useApp()` inside a component, never the static `import { message } from "antd"` (it renders outside the tree and loses theme + locale). Toasts remain the standard channel for surfacing mutation errors (don't render inline error text).
- **Stale-chunk self-heal in `__root.tsx`**: a module-level `vite:preloadError` listener triggers a single `window.location.reload()` (gated by a `sessionStorage` flag so it can't loop) when an old `index.js` references a hashed route chunk that no longer exists post-deploy. It looks like incidental event wiring — **don't strip it during cleanup**. It's the only thing protecting users on a stale tab from a Cloudflare Workers 404 after a redeploy. The flag self-clears on a successful `load`, so a future genuine stale chunk can still trigger recovery.
- Env vars are validated through `@t3-oss/env-core` in `apps/web/src/env.ts`. Required at build and runtime: `VITE_CONVEX_URL`, `VITE_CONVEX_SITE_URL`, `VITE_SITE_URL` (these are also declared as Turbo build inputs in `turbo.json`).
